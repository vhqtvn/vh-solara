## The machinery (packages/core/src/event.ts, verified at tag)

`EventV2.Interface.project(definition, projector)` appends to a
`projectors: Map<type, Subscriber[]>`. Every durable publish funnels through
`commitDurableEvent`, which runs ONE `db.transaction({ behavior: "immediate" })`
containing, IN ORDER:

1. read the aggregate's latest seq (EventSequenceTable)
2. replay-divergence checks (only for replays)
3. **duplicate EVENT-id check**: `select ... from EventTable where id = event.id`
   → `Effect.die(InvalidDurableEventError "Event ${event.id} already exists at
   aggregate ...")` — a re-publish of the SAME event id DIES (never upserts,
   never silently skips)
4. **the registered projectors run** (`for (const projector of list) yield*
   projector(committed)`) — INSIDE the same transaction
5. the caller's optional `commit(seq)` hook (local operational projection)
6. EventSequenceTable upsert + EventTable insert

⇒ **projection and event-append are ATOMIC**: if the process dies before the
SQLite COMMIT, neither the EventTable row nor the projected MessageTable/
PartTable row lands. Post-restart reads see committed transactions only —
this STRENGTHENS the restart-barrier claim (class-3: post-restart exact-ID
GET 404 ⇒ the MessageUpdated transaction never committed ⇒ the prompt never
persisted).

## The upsert-vs-die branch, answered per table

- **MessageUpdated projector** (`projector.ts`): `insert(MessageTable)
  .values(...).onConflictDoUpdate({ target: MessageTable.id, set: { data } })`
  — **UPSERTS (overwrite)** by message id. A delayed fiber re-publishing the
  SAME messageID overwrites the row; it does NOT die and does NOT create a
  second row.
- **PartUpdated projector**: `insert(PartTable).onConflictDoUpdate({ target:
  PartTable.id, set: { data } })` — **UPSERTS** by PART id. BUT parts are
  minted FRESH per prompt (`prompt.ts` resolvePart's `assign()` →
  `PartID.ascending()`), so a re-POST of the same text appends NEW part rows —
  **duplicate parts on one message**, rendered AND fed to model context
  (confirms addendum Q2; BLK-A2's live-redelivery prohibition STANDS).
- **Created projector**: `onConflictDoNothing` + `Effect.die(new
  SessionAlreadyProjected())` if the row already existed — duplicate session
  creation DIES.
- SessionInputTable (Prompted/PromptAdmitted projectors): the durable
  input-admission record keyed by messageID with promoted/admitted seq.

## prompt_async branch (the phase-2 session.error reliance)

`packages/opencode/src/server/routes/instance/httpapi/handlers/session.ts:311`
(`SessionHttpApi.promptAsync`), verified shape:

```
requireSession(sessionID)
promptSvc.prompt({ ...payload, sessionID }).pipe(
  Effect.catchCause(cause →
    logError("prompt_async failed", ...)
    events.publish(Session.Event.Error, {
      sessionID,
      error: new NamedError.Unknown({ message: Cause.pretty(cause) }).toObject(),
    })),
  Effect.forkIn(scope, { startImmediately: true }),
)
return 204 NoContent   // IMMEDIATELY — before the fork persists anything
```

- **Fork-before-persist confirmed at the branch**: the 204 returns before the
  forked fiber runs; persistence happens later via the events the fiber
  publishes (MessageUpdated/PartUpdated through the projector transaction).
- **session.error reliance is REAL but weakly typed**: the failure event is
  always `NamedError.Unknown` with `message = Cause.pretty(cause)` — a human
  pretty-print, not a machine code. Phase 2 may key "the fork failed" on the
  event's presence + sessionID match, but any classification (abort vs
  provider vs internal) is string-heuristic on the pretty text. Record this
  as a limitation when phase 2 consumes it.

## Implications for phase 2 (short)

1. Restart-barrier (certified class 3) is SAFE to build on the pinned
   transactional-atomicity: event+projection commit together or not at all.
2. The projector branch is now LOCATED but NOT "proven benign" for
   live-uncertain redelivery: message rows upsert (benign-looking) while part
   rows DUPLICATE on re-POST (behavior-altering). Per debate-3 A2/A9, the
   live-uncertain auto-redelivery class stays PROHIBITED (slice "2c" not
   scheduled) — the located branch confirms rather than lifts the blocker.
3. session.error is usable as a failure signal with the typed-field caveat
   above.
